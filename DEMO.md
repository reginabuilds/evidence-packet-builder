# DEMO SCRIPT — WEEK 07

## 3-minute walkthrough + 30-second reflection

### 0:00–0:25 — Frame the problem

“SEMOVI already has mobility data. My Technologist question is narrower: do we have enough observation coverage to know when the official representation stops explaining actual operation?”

Point to the **SIMULATED DATA** badge.

### 0:25–1:05 — Show the map

Explain:

- green = official representation;
- dashed orange = observed trip cluster;
- the observations are simulated phone/GPS telemetry;
- this is not a public map update.

### 1:05–1:35 — Run the mismatch scenario

Click **Run analysis**.

Point to:

- observation coverage;
- mismatch score;
- persistence;
- evidence package.

Say: “The system does not say the route is officially wrong. It creates a review signal.”

### 1:35–2:00 — Show uncertainty

Click **Low coverage** and run analysis.

Say: “This is critical. Low coverage means unknown, not stable. A system that cannot tell missing data from stability would create false confidence.”

### 2:00–2:30 — Show human decision

Return to **Mismatch**, run analysis, then click **Request field validation**.

Say: “The analyst owns the decision. The product does not publish a route, sanction a driver, or automate an institutional decision.”

### 2:30–3:00 — Connect to the experiment

Say: “The real experiment is not AI versus maps. It is current institutional workflow versus current workflow plus an operational-change signal. The success criterion is measurable time or cost savings without reducing decision quality.”

### 3:00–3:30 — What changed my mind

“I started with the belief that Mexico needed technology to capture driver knowledge. Existing systems forced me to kill that broad claim. I narrowed the hypothesis to data coverage and workflow efficiency. If SEMOVI already has sufficient information and its current workflow works, the correct technological decision is not to build.”
